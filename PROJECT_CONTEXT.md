## Purpose and settled decisions

- A configured owner sends a UTF-8 JSON file to a Telegram bot. The bot creates a native quiz and can publish a longer explanation on Telegraph. Content may be written manually or generated by a model; the bot itself calls no model API.
- The bot is general-purpose. It preserves authored content and adds no fixed teaching instructions, labels, or translations. The adult–child educational use case belongs to the example and optional prompt, not to bot behavior.
- The interface, operational messages, and documentation are English. The shipped educational example is Ukrainian. Input and resulting quizzes/articles support arbitrary Unicode languages. Keep Russian text out of tracked project material; this is a repository-content preference, not a restriction on user input.
- In the educational example, Question contains the lightbulb instruction and Description contains the situation. Authors may use these fields differently. The original learning goal was one concrete situation with alternative adult responses and reinforcement of the correct response; explanatory material is also supported.
- Description and Explanation use Telegram's native MarkdownV2. Question and Options are plain text. There is no HTML or formatting-mode selector and no custom MarkdownV2 parser or automatic plain-text fallback. Telegram validates rendered limits and syntax; local validation does not reproduce its parser.
- A `telegraph` object contains all article text. The literal `{{telegraph.url}}` inserts its published URL in supported quiz text fields; authors choose placement and link labels. `telegraph.text` uses the supported subset of ordinary Markdown, distinct from MarkdownV2. Telegraph was selected for longer, selectable text accessible by link; an image is not the intended reading format. Optional `.md`/`.txt` attachments remain supported.
- The authoritative JSON contract is [FORMAT.md](FORMAT.md), with the structure in [quiz.schema.json](quiz.schema.json). Preserve native API capabilities and documented limits rather than imposing Telegram editor limits.

## Invariants to preserve

- Only the configured owner's private JSON uploads create quizzes. Do not permit input to redirect output or override access policy. `correct_option` is one-based; option order is preserved.
- Quiz settings are anonymous, one correct answer, no option shuffling, and revoting enabled. The bot creates a new quiz for a new submitted file; it does not edit existing quizzes.
- Durable update claims prevent duplicate sends after repeated delivery or a restart. A send with an unknown outcome must not be blindly retried. This favors avoiding duplicate publication over guaranteed delivery.
- Telegraph publications are cached by content. Corrected quiz submissions with the same article material reuse the URL. An uncertain publication remains pending and blocks automatic republication until its outcome is checked.
- Preserve `STATE_DIR/state.sqlite3` across updates. It contains both update-processing state and article publication records. Do not delete it to bypass a failure.
- Run one process per bot token. Startup refuses an existing webhook rather than removing it. Runtime uses outbound HTTPS and long polling; no inbound endpoint is required.
- Keep credentials, populated environment files, private connection details, logs, and runtime state outside version control and release archives. Public deployment examples stay generic. Access to the repository does not imply access to the running server.
